Box1 Service Map with Edge Sites

The Box1 operations services after Site Expansion: two RHEL 10 image-mode VMs now act as remote warehouse sites. They send equipment readings and site events into Kafka through a local outbox, keep their own pick lists from inventory and shipment events, report their status to Asset Service, and ship traces, logs and metrics to the cluster collector. Edge site data flows

  1. Readings. The site's equipment simulator publishes over MQTT to the local AMQ Broker. site-gateway stores each reading in the site's PostgreSQL outbox, then publishes equipment.reading.v1 to box1.telemetry.events.v1, keyed by assetId, with a box1-site-id header and a traceparent.
  2. Site events. Pick confirmations, cycle counts and holds from the site-ops handheld UI go through the same outbox to box1.site.events.v1, keyed by siteId. Inventory Service consumes them as group inventory-site and dead-letters to box1.site.dlq.v1.
  3. Pick lists. Each site reads box1.inventory.events.v1 and box1.fulfillment.events.v1 as group site-gateway-<siteId>, keeps only its own reservations and commits offsets after storing them.
  4. Status. About every 15 s each site sends PUT /api/v1/sites/{siteId}/status to Asset Service with its own Keycloak client token (role site-reporter, siteId claim). Asset Service derives ONLINE, DEGRADED or OFFLINE (no status for 90 s); the console's Sites view reads it back.
  5. Observability. Quarkus OTLP and an in-guest OpenTelemetry collector send traces, journald logs and host metrics, including site_outbox_depth, to box1-collector, which feeds Tempo, LokiStack and Prometheus.
  6. Not connected. The sites never talk to the legacy ERP directly, and stay outside the ambient mesh.

How a site gets its software

  1. A merge to site-gateway (Quarkus monorepo: gateway, ops, simulator) publishes a FROM scratch bundle by digest and passes the security gate.
  2. The release opens a digest-bump PR in site-gateway-os, whose Containerfile copies the bundle into the RHEL 10 bootc image. One OS digest carries the apps.
  3. Each site instance (site-west, site-east) was created from the Developer Hub vm-instance template and pins its own approved OS digest in box1-workloads-dev. Identity comes from cloud-init (NoCloud) with the client secret passed by reference.
  4. Rollout is staged, site-east first, then site-west. On 2026-11-10 both moved to sha256:651d4a5f… (bundle sha256:26543a45…) by GitOps PR plus a digest-pinned bootc switch; greenboot passed on both. The automated staged rollout (#141) is not built yet.

Where Site Expansion stands

Verified live on 2026-11-10

  • Both VMs running the approved OS digest; both sites ONLINE in Asset Service.
  • Readings from both sites stored (114 for site_ds9, 151 for site_spacedock); one breach raised and cleared one alert; trace runs site → gateway → Asset Service.
  • Site identity: own status write 200, other site 403, anonymous 401.
  • Site events (holds) and a pick confirmation recorded by Inventory Service; test orders appeared only on their own site's pick list.
  • Site logs, host metrics and traces visible in LokiStack, Prometheus and Tempo.

Not verified or not run yet

  • Console Sites page not yet opened in a browser.
  • Shipment closing a pick list, cycle-count reconciliation and replay.
  • Drills: site goes dark (NIC detach), bad release rollback by greenboot, reboot.
  • Agentic Operations citing a site's last-seen gap and buffer depth.

Not built

  • Per-site Kafka identity and ACLs, blocked on box1-docs#71; sites currently mark records with the box1-site-id header.
  • Egress NetworkPolicy for the site namespaces.
  • Automated staged rollout (#141); gating orders on site picks (#134); native builds (#135).

agentic-operations is a read-only consumer: it reads the five *.events.v1 topics into an in-memory evidence window, never commits offsets and never produces. It answers the console's Assistant chat and incident analyses with the in-cluster vLLM model box1-coder, using read-only HTTP tools under the caller's own token.

Equipment can still post readings over HTTP (POST /api/v1/telemetry/readings, role telemetry-writer); the edge sites use Kafka instead. "Contract only" means a group is listed in TOPICS.md but no service consumes it yet.
